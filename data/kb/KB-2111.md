# KB-2111: Aurora AR-900 9.1.x upgrade to 9.2.0 fails when BGP add-path is enabled

## Summary
During an in-service upgrade from Aurora AR-900 9.1.4 or 9.1.6 to 9.2.0, the installer can fail after image staging when BGP add-path is enabled. The upgrade rolls back to the previous release, but BGP sessions may remain down for 1 to 2 minutes while adjacency state is re-established.

## Symptoms
The upgrade process starts normally, downloads and stages the 9.2.0 image, then aborts before rebooting into the new release. The device returns to the prior software version and the system log records an add-path state migration failure with error code ERR-UPG-1307. In affected environments, the rollback also interrupts BGP forwarding temporarily, and peers may show session resets until control-plane state converges again.

This issue is seen only when BGP add-path is configured on at least one neighbor and the router is advertising more than 1,000 paths. Platforms without add-path, or with smaller path tables, do not exhibit the failure.

## Diagnosis
1. Run `show version` and confirm the device is on 9.1.4 or 9.1.6 and the attempted target is 9.2.0.
2. Run `show bgp summary` and verify that at least one BGP neighbor is established and configured for add-path capability.
3. Run `show bgp neighbors detail` and look for add-path send/receive state on the affected neighbor; the issue requires add-path to be enabled on at least one session.
4. Run `show bgp routes advertised` or the equivalent advertised-paths view and confirm the router is advertising more than 1,000 paths.
5. Run `show log` or `show logging` immediately after the failed upgrade and look for ERR-UPG-1307 together with a precheck or migration message referencing add-path state.
6. If the upgrade entered rollback, run `show system upgrade status` and verify that the active release remains the old image rather than 9.2.0.

Example output:

```text
2026-03-14T02:13:07Z %UPG-4-STAGE: image 9.2.0 staged successfully
2026-03-14T02:13:08Z %UPG-3-PRECHECK: migrating session database
2026-03-14T02:13:08Z ERR-UPG-1307 add-path state migration failed: stale capability bitmap detected on neighbor 203.0.113.2
2026-03-14T02:13:09Z %UPG-4-ROLLBACK: reverting to 9.1.6
2026-03-14T02:13:11Z %BGP-5-ADJCHANGE: neighbor 203.0.113.2 down, reason: reset during upgrade rollback
2026-03-14T02:14:22Z %BGP-5-ADJCHANGE: neighbor 203.0.113.2 up
```

## Root cause
The upgrade migrator in the 9.1 family does not translate the BGP add-path capability bitmap into the 9.2.0 session schema. When the installer precheck encounters the stale capability record, it cannot convert the session database in place and aborts the upgrade.

Because the abort occurs after staging but before completion, the platform rolls back to the previous release. The rollback itself is expected behavior, but it briefly resets BGP sessions while the control plane restores the pre-upgrade state.

## Workaround
1. Before starting the upgrade, remove BGP add-path from the affected neighbor configuration so the migrator does not encounter the unsupported capability record.
2. Save the configuration, then restart the in-service upgrade to 9.2.0 and allow the router to complete the transition.
3. After the router is fully running 9.2.0 and BGP sessions are stable, re-enable add-path on the required neighbor if the design depends on it.
4. If the router is already stuck in rollback, let it boot back into the prior release, remove the add-path configuration, and then retry the upgrade.

```text
configure
router bgp 65001
no neighbor 203.0.113.2 add-path send
```

## Resolution
The defect is fixed in release 9.2.1. In that release, the upgrade migrator converts add-path state during the image transition, so the 9.1.x to 9.2.x upgrade completes successfully when BGP add-path is configured.
