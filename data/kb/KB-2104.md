# KB-2104: Aurora AR-900 IPv6 SLAAC prefixes are removed too early after router advertisement suppression

## Summary
On Aurora AR-900, hosts using IPv6 SLAAC can lose their global address shortly after router advertisements (RAs) are suppressed or filtered on the access VLAN. The router continues to show the delegated prefix in configuration, but host reachability fails once the local prefix state ages out on the 3-minute hold timer. This behavior affects all releases when RA suppression is used with SLAAC.

## Symptoms
Hosts on an access VLAN lose their global IPv6 address about 180 seconds after the last valid router advertisement is filtered or suppressed, even though the configured valid lifetime is 7200 seconds. The loss is most visible when existing TCP sessions reset or new TCP connections fail after the preferred lifetime expires. Neighbor Discovery lookups also begin to fail for affected hosts because the prefix is withdrawn locally before the advertised lifetime ends.

The AR-900 itself still shows the delegated prefix in the configuration, which can make the issue appear intermittent or limited to the client side. The problem is reproducible on any release when RA suppression is used for maintenance or upstream filtering.

## Diagnosis
1. Run `show ipv6 interface vlan 10` and confirm the interface has SLAAC configured and RA suppression is enabled or has recently been applied. The issue is consistent with an interface that should be advertising a prefix but is no longer receiving upstream RAs.
2. Run `show ipv6 neighbors` and look for host entries on the access VLAN transitioning to incomplete or expiring state shortly after RA suppression begins. A broad loss of reachable neighbors on the VLAN supports this problem.
3. Run `show ipv6 route` and verify the delegated prefix is still present locally while host connectivity has already dropped. The prefix remaining in the routing table does not rule out this issue.
4. Run `show log` or `show logging` and look for `%IPV6-4-RA-LIFETIME` entries with timestamps around the time clients lose connectivity. These messages indicate the prefix lifetime is being aged by the local hold timer rather than the configured valid lifetime.
5. If needed, enable `debug ipv6 nd` briefly and confirm that no new router advertisements are being accepted while the local prefix state expires after approximately 180 seconds.
6. Check whether the access VLAN is using SLAAC rather than DHCPv6 stateful addressing. The issue requires SLAAC on a VLAN where RA suppression is active or where upstream RAs are being filtered.

## Root cause
The router tracks SLAAC prefix lifetimes from received advertisements instead of from the locally configured valid and preferred timers when RA suppression is active. Once the upstream advertisements stop, the local prefix state is aged out by the 3-minute hold timer rather than the advertised lifetime, which prematurely withdraws host configuration.

This is a design constraint in the current implementation: when RA suppression is used on a VLAN that depends on SLAAC, the device does not preserve the prefix purely from the configured lifetime values. As a result, host addresses can be removed early even though the interface configuration still shows the delegated prefix.

## Workaround
1. Avoid suppressing router advertisements on the active user VLAN when that VLAN depends on SLAAC for host addressing.
2. If advertisement suppression is required for maintenance or upstream policy, move the affected segment to DHCPv6 stateful addressing so hosts can retain IPv6 configuration independently of SLAAC prefix advertisements.
3. If the operational requirement is to keep SLAAC, ensure the RA hold timer is configured to exceed the preferred lifetime so the local prefix state is not withdrawn before clients finish using it.
4. After applying the chosen workaround, verify with `show ipv6 interface vlan 10` that the VLAN is advertising as expected or that the alternate addressing method is active, and confirm clients retain their global IPv6 addresses beyond 180 seconds.

```text
configure
interface vlan 10
ipv6 nd ra-suppress
```

## Resolution
No software fix is required; this is a design constraint when RA suppression is used with SLAAC on Aurora AR-900. To prevent recurrence, do not suppress router advertisements on VLANs that rely on SLAAC, or migrate those segments to DHCPv6 stateful addressing. If suppression must remain in place, configure the RA hold timer so it exceeds the preferred lifetime and does not age out the prefix before host configuration should expire.
