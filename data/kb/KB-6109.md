# KB-6109: HX-5000 7.2 oversubscribed 100G egress queues drop bursts above 85 percent utilization

## Summary
On Helix HX-5000 release 7.2, oversubscribed 100G egress ports can drop microburst traffic even when average utilization appears below line rate. The issue is most visible on interfaces carrying multiple active priority groups, where transient bursts exceed the scheduler’s reservation depth and create sustained tail drops.

## Symptoms
Affected systems show output drops on 100G ports that are not fully saturated by average traffic. Operators typically report that `show queue counters` reports tail drops increasing by several thousand packets per minute, while latency for adjacent flows rises from sub-millisecond values to more than 12 ms during busy periods.

The condition is triggered by microbursts larger than 48 KB on oversubscribed links. In many cases, the interface appears healthy in standard utilization views, but queue statistics show rising discard counters and intermittent `%BUF-3-OVERFLOW` messages in the system log.

## Diagnosis
1. Run `show interfaces ethernet 1/52` and confirm the port is operating at 100G with sustained utilization in the 70 to 80 percent range.
2. Run `show queue counters interface ethernet 1/52` and look for tail drops increasing steadily, typically by thousands of packets per minute, while no physical errors are present.
3. Run `show interfaces transceiver detail` and verify the optic is healthy so the drops are not caused by link degradation or FEC errors.
4. Run `show logging | include %BUF-3-OVERFLOW` and confirm repeated overflow events correlate with periods of bursty traffic on the affected port.
5. If available, run `show hardware buffer utilization interface ethernet 1/52` and check whether queue occupancy approaches or exceeds 85 percent during the loss window.
6. Compare latency-sensitive flows on adjacent uplinks with `show queue counters` to confirm the drops follow oversubscription rather than an isolated application path issue.

## Root cause
The defect is in the 7.2 egress scheduler on HX-5000 100G ports. The scheduler uses a fixed 8-cell reservation window, which underestimates burst depth when multiple priority groups are active on an oversubscribed interface.

Once queue occupancy rises above 85 percent, the local buffer watermark is reached too late in the transmit path. As a result, the device discards frames instead of preserving the burst through shaping, which produces sustained tail drops and secondary latency inflation on neighboring flows.

## Workaround
1. Reduce burstiness on the upstream sender with traffic shaping or pacing so microbursts remain below the 48 KB trigger point.
2. If possible, distribute the traffic across additional uplinks so no single 100G egress port remains above 85 percent sustained utilization.
3. For latency-sensitive applications, place the affected traffic into a dedicated queue on the impacted interface and validate the queue policy after the change.
4. Apply the interface-level workaround on the affected port to use a separate queue-set and disable priority flow control when the design does not require lossless behavior.
5. After the change, monitor `show queue counters interface ethernet 1/52` and `show logging | include %BUF-3-OVERFLOW` to confirm tail drops stop increasing and overflow events cease.

```text
configure terminal
interface ethernet 1/52
queue-set 3
priority-flow-control disable
```

## Resolution
This defect is fixed in release 7.4. In 7.4, the scheduler reservation window was expanded and buffer watermark checks were moved earlier in the transmit path, which prevents the burst loss behavior seen on 7.2 oversubscribed 100G egress ports.
